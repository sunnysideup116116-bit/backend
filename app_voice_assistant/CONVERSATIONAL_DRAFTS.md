# 語音草稿與任務接續

本輪支援傳訊、建立行程與修改行程。沿用既有 JWT、任務儲存、Flutter
執行器、額度及 Risk 規則；不新增服務、資料庫集合或連線網址。

## 使用方式

- 「幫我傳訊給小安」先保存對象，只追問訊息內容。
- 「換成小美」「內容改成週六一起喝咖啡？」更新原草稿，保留其他欄位。
- 行程可說「改七點」「地點改成公園」「日期改到下星期六」。簡短時間
  修正保留原有上午／下午；有明確時段時以新時段為準。
- 「先等一下」保存草稿；查詢天氣、行事曆、額度等可暫停待確認草稿。
- 「繼續剛才」重新檢查草稿。多份草稿需要先選擇；不會自行執行。
- 展開語音視窗，可看見草稿摘要、剛修改的欄位與修改／保留／確認按鈕。

一般語句由 Live 呼叫草稿工具解析，常見的簡短改口另有固定解析路徑。
不會將任意文字當成待送訊息；固定解析無法完整理解時交回模型。
狀態模式仍只處理額度、冷卻、回執與關閉指令，不執行雲端草稿工作。

## 契約及確認

- capability 回報 `conversation_drafts_version=1`；前端透過
  `feature_status.conversation_drafts` 啟用。舊前端維持既有操作流程。
- template／proxy 共用 `manage_voice_draft`，分別為 18／8 個工具；legacy 不變。
- 工具只接受固定 intent 和欄位，不接受任意使用者 ID 或執行命令。
- `task_update` / `task_snapshot` 增加可選 `draft`：摘要、欄位、缺少欄位、
  修改欄位、是否可編輯。原本的 task 狀態與 revision 契約維持不變。
- `task_input` 提交欄位差異；`task_pause` 保留目前草稿。兩者都檢查本人與
  revision。重新開啟後由既有任務快照恢复，再由使用者選擇繼續。
- 修改會清除舊 action ID，重新產生確認。變更對象／目標時清除舊 target_ref。
- 發送與失效處理都以目前確認 ID 做原子比對，避免跨連線送出舊草稿，或
  舊連線關閉時撤掉新確認。模型不能在建立或修改的同一回合自行確認。
- 恢復會重查權限、目標有效性及日期。送出仍走原本額度及 Risk 檢查。
- 已送出、執行中或結果不明的寫入不能透過草稿介面重送；查詢回執仍是
  唯讀，不觸發新的傳送。

## 受阻及進度

後續版本依使用者要求將額度、冷卻與回執改為語音詢問，移除其文字輸入及查詢按鈕；權限設定等其他操作選項保留，不提供自動重送。
直接操作顯示目前正在查詢行事曆、更新行程或確認傳送結果。等待輸入或確認
在任務卡中不顯示持續執行中的進度動畫。任務結果保留先前的 quota/delivery/cooldown 資料。

## 驗證及啟用

新增回歸涵蓋部分草稿、改口、跨頁／重開、過期日期、多人同名的既有執行器、
權限撤銷、舊確認、雙連線、已送出／未知結果防重做，以及窄螢幕編輯與按鈕。
測試使用合成帳號、記憶體資料庫及模型替身。

2026-09-21 驗證結果：後端整批 372 項、Flutter 語音相關 174 項通過；
最後補強排程式查詢插話後，相關後端 79 項再次通過。Android debug APK
建置、共用能力清單一致性、`start_all.sh` shell 語法與 `git diff --check` 通過。
Dart 分析無 error/warning，保留既有 client 的一項大括號風格 info。

GitNexus 已完整刷新兩個索引。累積未提交的 tracked 變更（含前一輪）為
Server 19 files／73 symbols／87 flows、DatingApp 13 files／95 symbols／31 flows，
均為 CRITICAL；結構化 detect_changes 無 partial/truncated 標記。圖譜本身
仍有跨語言連結與流程數上限，新增未追蹤檔案另由原始碼審閱及回歸覆蓋。

部署仍使用 `Server/start_all.sh`，Flutter 安裝同版 APK。此變更不修改固定
服務位址與連接埠。本次工作不包含正式部署；真機收音、噪音及藍牙體驗需在
實體 Android 上驗收。

完整約會規劃、聊天練習與長期偏好管理保留給後續版本。

## 第一輪整合補強

- 修改行程時，確認摘要顯示新名稱、地點、備註及明確清除的欄位；新增行程也顯示備註。
- 草稿查詢先篩選本人可接續的草稿，再套用筆數上限，避免近期完成紀錄擠掉舊草稿。
- 收到確認時重新檢查目前權限。權限已關閉則保留草稿並撤掉舊確認，重新授權後仍須再次確認。
- 新增三項回歸；後端整合測試更新為 375 項通過。`start_all.sh` 語法與兩個 repository 的差異格式檢查通過。
- 本次補強只改後端，Flutter 可沿用上一輪建置的 APK；未執行正式部署。
