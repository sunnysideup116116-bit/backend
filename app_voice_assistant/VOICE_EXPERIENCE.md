# 語音阿月：規劃、偏好、App 說明與語音體驗

本輪沿用共用額度、Risk、地點、行事曆、記憶與確認服務，不新增服務或連接埠。
前後端能力清單版本為 16；template 21 個、proxy 11 個、legacy 39 個模型工具。

- 「這個 App 可以幫我做什麼？」「要怎麼安排共同約會？」
- 「十月十二日晚上六點，在台北和小安出去，每人五百，幫我比較方案。」

- 草稿中說「時間往後半小時，地點不變」「先給我看內容，還不要傳」。
- 「不是取消星期六，是取消星期日那個」會以肯定的日期為約束；目標不吻合就追問。
- 「額度還剩多少」「冷卻還要多久」「剛才有送出嗎」。

## 約會比較

`plan_date` 對應 `date.plan`，只準備／選擇方案。Flutter 平行查詢已授權
行事曆與可選的本人記憶，再沿用 Public Ayue 的地點搜尋。缺少城市、日期、
開始時間時只追問一項，不提前進行地點模型查詢。

方案只由 API 實際回傳的地點卡建立，最多三項、去除重複地點。卡片顯示日期、
時間、來源、查詢時間、採用的偏好及已知／未知的價格、營業和步行資料。
來源提供的最低新台幣價格超過預算時排除；價位等級不換算成虛構金額。
缺少價格資料的地點明確標示待確認。一般營業時間不代表預約日期一定營業。

未指定長度先用 90 分鐘並在草稿備註揭露，可指定 30–480 分鐘。行事曆資訊
不完整時不宣稱有空，有重疊就顯示衝突；不推測對方私人行程，也不訂位。
選擇後回傳邀請／行程草稿資料，仍需經 `manage_voice_draft` 與原確認、Risk
流程才可寫入或傳送，不會因為點選方案就自動執行。

方案存在裝置上，以本人帳號隔離，30 分鐘後失效。新條件會撤掉舊方案參照；
過期、其他帳號、晚到的舊結果及撤銷記憶權限後的含偏好方案均拒絕使用。
規劃新的一次外出用 `reset=true`，接續這次則保留既有欄位。

## 偏好與 App 知識

長期偏好沿用 `getProfileMemories` / `addProfileMemory`；新增仍須確認。
`forget_preference` 對應 `memory.disable`，只接受完整標籤，讀回本人記憶並
唯一解析後才使用內部 key 停用；模型看不到 key，也不能指定任意帳號。
重複標籤需追問，停用需確認，停用後清除先前的規劃快取。

`ignore_preferences`、`ignore_budget` 與本次 requirements 只作用於本次方案，
不寫入長期記憶。未授權記憶讀取就不查記憶，仍可依明確條件規劃。

`explain_app` 與 `get_voice_capabilities` 從實際 ACTIONS/GUIDES 產生說明、
操作步驟與權限可用性，不把靜態長篇手冊塞入每輪模型上下文。新的裝置操作
要求 `feature_status.voice_experience=true`；舊前端收到更新提示。

## 語音介面與量測

依本輪使用者要求移除「額度與傳送狀態」區、文字輸入與狀態查詢按鈕。
一般語音仍可問額度／冷卻／回執；耗盡後停止雲端連線，只在可用的 Android
裝置端辨識與離線 TTS 下提供固定語音查詢。無離線能力時顯示說明，不退回
雲端、不提供文字輸入。說「恢復語音」會先重新檢查額度，仍為零就不連線。

唯讀操作省去裝飾性指標移動。新增單調時鐘量測：VAD／逐字稿完成到首段
音訊進入播放器、第一個操作結果、單次操作時間與收到打斷事件到停止播放。
這些是軟體邊界量測，不等於真實嘴巴停止到喇叭出聲的聲學延遲。

縮小浮層只保留放大與關閉，已依使用者要求移除回饋選單。`voice_metric` 只接受固定事件與
0–600000 毫秒整數，每 session 上限 240 筆；不傳錄音、逐字稿、人物或帳號 ID。
未調整現有 VAD 預設值；實機噪音、耳機與藍牙的調整需依實測結果決定。

ports 保持不變。本輪沒有推送或重啟正式服務。

## 牽線匿名、等待回覆與版面更新（2026-09-21 後續）

未雙方同意的牽線維持匿名：draft、pending、declined、expired 等狀態不再
向前端附上對方姓名。accepted 仍需 canonical decision／history 驗證才揭露。
本人 JWT 與對話授權不變；既有聊天聯絡人的公開稱呼不受影響。

後端卡片／歷史投影及 Flutter 本機快取在送入畫面、語音 context、工具回覆前
移除對方稱呼，並處理舊理由、來源摘要、共同點中的已知別名；路由 ID 保持穩定。
canonical 名稱只在伺服器用來消除舊資料中的姓名，不交給模型。
既有語音短摘要可能已記住提前曝光的姓名，因此未帶 `anon2:` 標記的摘要不再
讀入新語音或摘要模型；不刪除舊記錄，不修改長期偏好。新 session 摘要正常保存。

已找到並修正兩條可能造成工具問答久候的程式路徑：

- 一般配對進度原本還會查聯絡人／個人資料，現在只在需要已建立連結的名字時查詢；
  canonical 狀態查詢限 12 秒，非必要聯絡人／歷史補查限 3 秒。唯讀逾時不重做操作。
- 非同步工具完成後，原本若未收到 Live `turn_complete`，結果可能一直留在佇列。
  現在以單調時鐘檢查：沒有使用者說話、沒有待完成 App／工具操作、模型閒置 8 秒時，
  恢復已完成結果的回覆。只交付既有結果，不重新呼叫工具或重送寫入。

Flutter 顯示目前查詢／執行階段與等待秒數，區分「App 還在執行」和「結果已回來，
等待語音整理」。工具完成後重新啟動回覆 watchdog；20 秒仍無回覆則恢復連線，
不重播原始要求。額度耗盡、停止語音與結束回覆均清除等待指示。
這是合成事件回歸證實的修正，沒有宣稱涵蓋所有真實網路或模型端延遲原因。
