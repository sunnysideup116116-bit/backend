# Ayue V3 Stages 5–7 Implementation Record

## Scope

Stages 5–7 implement the migration sequence defined by the canonical Flutter guide:

- Stage 5: stable reads and canonical mobile bootstrap.
- Stage 6: Public Ayue NDJSON streaming and typed presentation.
- Stage 7: match CAS, Calendar, relationship dates, and isolated Private Ayue state.

## Stage 5: Stable interfaces

- Added a dedicated V3 mobile client without replacing unrelated Appwrite or social-post services.
- Preserved the existing backend base URL build setting.
- Added typed health, initialization, contact, message, setting, Calendar, match, and relationship-date boundaries.
- Replaced the removed Big Five initialization route with the canonical `/api/chat` initialization request.

## Stage 6: Public stream

- Added an incremental UTF-8 NDJSON decoder that tolerates arbitrary byte boundaries.
- Enforced allowlisted event names and exactly one terminal boundary.
- Public sends use only `/api/direct_chat/stream`.
- Added delayed singular progress, bounded failure presentation, multi-message rendering, and additive presentation surfaces.

## Stage 7: Stateful UI

- Durable match search replaces immediate `/api/match` result assumptions.
- Visible cards send guarded `/api/match/decision` requests and refresh without replay after stale state.
- Added typed Calendar agenda, creation, permission, and revision-bound cancellation surfaces.
- Added shared-date state and confirmation projection inside the private mediator view.
- Private Ayue uses its own V2 stream and remains isolated from Public V3.

## Safety boundaries retained

- No file or symbol under `Server/ayue_for_demo/` was changed.
- No database cleanup, demo reset, graph clear, or destructive endpoint was called.
- No secret value was copied into Dart or Markdown.
- Existing `DatingApp/run_test.py` and `DatingApp/lib-backup/` changes remain untouched.
- No Git commit is created during this integration stage.
