# Ayue V3 Stages 8–9 Implementation Record

## Scope

- Stage 8 completes typed Flutter surfaces left after stream, match, Calendar, and Private Ayue migration.
- Stage 9 restores the existing pair-chat risk policy at the V3 persistence boundary and completes integration acceptance.

## Stage 8: Remaining typed product surfaces

- Public history restores assessment state; exit uses `assessment_action=cancel` on the same stream transport.
- Recent-context extraction uses bounded 0.5/1/2/4/8-second polling and accepts only a higher revision.
- Public mentions select at most three contacts returned as accepted by the canonical backend.
- Relationship quiz supports read, start, answer, wait, result, restart, and cancel; the removed random-topic route is absent.
- Settings use the canonical proactive-frequency enum and expose owner memory disable actions by server key.

## Stage 9: Pair-chat safety and acceptance

- Flutter sends a stable client-attempt identifier with each pair-chat message.
- The backend applies mandatory risk policy before receiver-visible persistence.
- `restricted` remains delivered; `blocked` and unavailable assessments remain non-delivered.
- Allowed owner messages use deterministic insert-once persistence and history excludes blocked documents.
- Public V3 Planner/Scheduler and Private V2 remain unchanged by pair-chat safety wiring.

## Retained safety boundaries

- No database cleanup, graph reset, or destructive demo endpoint is called.
- Raw risk diagnosis, classifier evidence, state vectors, prompts, IDs, and intervention payloads are not projected to Flutter.
- Existing `DatingApp/run_test.py` and `DatingApp/lib-backup/` changes remain outside the integration stage.
- No Git commit is created.
